Mirage Console

developer debug console · v2

Redux DevTools for your agent's data plane. Scrub every action in a workspace, watch the state it mutated, and trace any byte back to the step that touched it. The workspace is the store; the real I/O mirage observes are the actions; one time-travel cursor sweeps it all — and because mirage is the data plane, it doubles as a live explorer of the connected sources with a bidirectional data ↔ trace bridge.

Store = Workspace

One mirage workspace is the container. The home shows all traces and all events in it — a run-rail to spot the red run, and a unified action stream beneath.

Actions = Real I/O

Every row is observed ground truth — an OpRecord at observe.record(): path · bytes · source · cache · fingerprint. Not the model's self-reported tool args.

State = Reconstructed

The cursor folds trajectory[0..idx] into the workspace state at that moment — overlay, mounts, reads-so-far, run tree — with the exact per-action diff.

The spine — one tree, folded (the bottom is the moat)

Leverage — do NOT rebuild
▸OTel SDK + GenAI/OpenInference conventions — context propagation, the LLM/tool/retrieval span model the whole industry converges on. Your AG-UI events are a bespoke re-derivation of this; align them.
▸Storage engines — ClickHouse/Postgres for the log, object storage for blobs. Don't write a database.
▸Aggregate dashboards & LLM-eval — Langfuse / Phoenix self-hosted; feed them via OTel for cross-run analytics and judging. The ScoreCard harness interops here.
Build — only these (the moat)
▸The mirage.vfs.* data-plane convention — op/path/source/mount/bytes/cache/fingerprint/revision. No standard models this. It's the moat vocabulary; you own it (and can upstream it).
▸The event-sourced replay log — single total order, immutability, content-capture-on-read, snapshots. Observability stacks sample & aggregate; replay needs completeness & determinism. Different discipline.
▸The console + time-travel engine — data-plane scrubbing + intent↔action↔effect + the data↔trace bridge. No existing UI does this.
⊘Honesty / the one real cost: true data-plane replay requires capturing the bytes at read time into the blob store (with redaction + sampling + TTL policy). Without capture you fall back to today's limit — backing pinned at stand-up, ops replay but content doesn't. Capture-on-read is the backend change that makes "FULLY replayable" actually true.
